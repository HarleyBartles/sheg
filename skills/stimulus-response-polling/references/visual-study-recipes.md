# Visual study recipes

Use these recipes for frozen screenshots, article images, character sketches, and bounded script evidence. Sheg runs authored typed questions over saved material and respondent profiles; Clef supplies model evidence. These studies do not observe human attention, reading, comprehension, or preference.

For a visual question, prepare and inspect each saved image with `image_import` and, when needed, `image_scale`; explicitly bind the intended image IDs in each question. Use the exact returned asset metadata in the request. In pixel mode, Clef receives the pixels and the supplied caption in a structured visual-material field; it omits `altText` from the pixel prompt. Sheg does not render the caption into an article layout. State where the image and caption are hypothetically placed, and do not duplicate the caption in article text unless that authored text is intentionally part of the article stimulus.

## Article image placement and flow

Use a whole-article poll when you want to compare hypothetical insertion points with every article section available to the model. Freeze text materials in this order: `section-1`, `section-2`, `section-3`, `section-4`, `section-5`; keep the saved `article-image` separate with its exact alt text and caption. The supplied caption accompanies the image as structured visual material; material order is not a rendered layout, so state where both image and caption would appear in each task instruction. Do not duplicate the caption as article text unless it is intentionally part of the authored article stimulus. For example, compare A after Section 1, B after Section 3, and C after Section 4.

Author a separate Noul task for each position and each question dimension. Use five dimensions: relevance to the adjacent section, continuity of flow, distraction from the following section, help understanding its point, and expressed interest in continuing into that next section. Example task: `{ "type": "noul", "id": "interest-at-b", "instructions": "Given the complete article and the illustration hypothetically placed after Section 3, would this reader want to continue into Section 4?", "criteria": { "true": "The reader would choose to continue into Section 4.", "false": "The reader would choose not to continue into Section 4." }, "visual": { "mode": "pixels", "materialIds": ["article-image"] } }`. For the other dimensions, author criteria that name the exact relation or section in question; do not treat expressed interest as measured continuation. Use IDs such as `relevance-at-b`, `continuity-at-b`, `distraction-at-b`, `comprehension-at-b`, and `interest-at-b`, repeated with a distinct position suffix for each point. All five article sections, image, profile, and pre-question history stay the same; only the stated hypothetical point and the corresponding adjacent section change. Independent tasks share one frozen state and never receive sibling answers.

Run `run_inspect` with the actual cohort, asset metadata, all 15 tasks, available providers, and a proposed `maxCalls`. Use its provider fit and minimum-call report to set the physical-attempt cap, including retry allowance; do not infer calls from answer count. With automatic selection, pixels make Clef eligible or necessary according to the enabled catalogue and settings. Query each authored `questionId` with `run_query`, or retrieve all typed results using `run_get` with `view: "answers"`. The result asks what modeled profiles would want when given the whole article and a hypothetical image location. It does not measure first-encounter continuation, comprehension, or real reading behavior. Because a different point also changes the next section, this does not isolate image presence from adjacent content.

When the decision is whether the image itself contributes at one boundary, use a staged reached-reader journey instead. Expose Section 1, ask a typed continue/stop Choice, and route only `continue` to Section 2; repeat for Section 2 and Section 3. Route only Section 3 continuers to a fork at the Section 3/4 boundary. The image branch exposes the bound image in pixels, then Section 4; the text-only branch exposes the identical Section 4 without the image. Ask the same Section 4 question in both branches, for example `Would you continue into Section 5?`, with the same `continue` and `stop` option meanings, a shared `comparisonKey` such as `section-four-interest`, and `responseHistory: "include"`. Route each branch's own `continue` answer to Section 5 and its `stop` answer to a terminal outcome. If the image treatment includes a caption, attach it to the image material and state its intended placement; do not also repeat it as Section 4 copy.

The response after Section 3 is the fork eligibility gate. It is not a prediction about people who never reached that boundary. Later text history carries facts supplied by the agent and typed outcomes, for example: “After Section 3, this respondent chose to continue. At the boundary they saw the supplied image described as ‘a yellow flower in an orange pot.’” This illustrates the meaning of compact history, not a literal serialized packet. Image bytes are sent to Clef only when the later question binds the saved image again.

Use `providerSelection: {}` for Sheg-managed provider choice, then inspect the planned prefix and fork. For the two same-key image conditions, Sheg keeps provider and model fixed so the image is the intended change; if pixel capability is required, both branches may use Clef. If each of three prefix tasks costs one call per respondent and every reached respondent gets both fork tasks, the initial estimate is `3 * cohortSize + 2 * reachedAtFork`, plus reached Section 5 calls and retry allowance. This is only a planning estimate: use `run_inspect` to set the cap from the actual batching plan. Read `run_get` with `view: "journey"` for reached membership, complete and incomplete pairs, branch outcomes, packet fingerprints, and provider/model evidence. Query the two branch question IDs separately when composing a follow-on. Missing, pending, failed, or unreached branches are not stop answers. This is a matched model comparison, not a randomized human experiment.

## Rendered-page comparisons

Begin by deciding whether the question is about each version's adequacy or a direct preference between versions. For independent adequacy, ask the same typed question of each supplied screenshot in a separate equivalent context, holding respondent profile, question, rubric, state, provider, and model fixed. A matched journey fork can create those conditions for the same respondents who reach a chosen boundary. A direct preference is a different question: bind both screenshots to one image Choice, use neutral stable labels and an authored tie or no-preference option, and do not describe the selected option as proof that it is readable or effective.

If the screenshots change image position, typeface, and size together, decide whether the treatment is intentionally that whole bundle. To isolate a factor, change one variable at a time; if interactions matter, author a design that compares the combinations rather than attributing a bundled result to one change. Record viewport dimensions, capture bounds, render scale, font identity and load status, and treatment notes when supplied. Mark missing capture facts unknown. Do not invent provenance.

When the question is whether screenshot text is legible, do not put the exact page copy into the same packet as plaintext; that lets the model answer from text without reading the rendered image. Ask separate content questions when the copy is needed for meaning. Use pixel mode for visual judgments and supply factual alt text for provenance; the pixel projection omits alt text. A described-mode question tests the supplied description rather than the image pixels.

Sheg's image scaler preserves the full image and only scales it; it does not crop, tune quality, or guarantee small text stays legible. Inspect the exact prepared candidate, verify it still shows the difference under study, and let the user choose which version to submit. Do not claim typography expertise, eye tracking, conversion, or real reader behavior from Clef answers.

For independent adequacy, assess each screenshot in its own equivalent question context with the same profile, instruction, rubric, provider, and model; bind only that version's image. For the same reached respondents in one run, place the two tasks after a matched fork, give them one `comparisonKey`, and hold their typed meanings and history policy constant. Example: `{ "type": "noul", "id": "layout-a-readable", "instructions": "Can a reader at the supplied viewport read the body text in this screenshot without zooming?", "criteria": { "true": "The body text is legible at the supplied viewport without zooming.", "false": "The body text is not legible at the supplied viewport without zooming." }, "visual": { "mode": "pixels", "materialIds": ["layout-a"] } }`. Give the parallel task a distinct ID and bind `layout-b`; do not include the exact page copy as plaintext in either readability packet. A separate direct-preference question can bind both images in one pixel Choice with stable labels and an authored no-preference option. Preference is not evidence that either version is adequate.

## Character sketches

For unprompted trait reading, use a context without the target character brief or target-trait description. Author a small set of typed trait questions in advance, such as separate Noul questions about whether the sketch reads as confident and as curious. This measures responses to those authored dimensions; it does not discover arbitrary traits or return a free-form explanation. The question itself names and therefore cues each dimension, so this is unprompted only relative to the withheld brief, not a fully uncued impression. Bind the supplied sketch in pixel mode. Keep any later prompted brief-fit assessment in a separate context so the unprompted response cannot inherit the target traits.

For prompted fit, include the authored brief and ask about each meaningful dimension separately. A brief such as “heroic and intelligent” can use one typed proposition per trait so one strong dimension does not hide a miss on the other. Optional Choice questions can probe authored unintended impressions. These remain judgments against the supplied brief, not an objective design winner or a human audience result.

For example, prepare four selected portraits with IDs `sketch-a` through `sketch-d`; bind the exact four in pixel mode. Ask separate Noul questions such as “Does sketch A read as heroic under the supplied brief?” and “Does sketch A read as intelligent under the supplied brief?”, each binding only `sketch-a`; repeat for each selected sketch. Include the written brief in these prompted-fit questions. If the decision is which sketch to advance, add a separate four-way image Choice with stable option IDs mapped to those four image material IDs and a `no-preference` option. Do not let one winner hide which trait was weak. If the fifth sketch matters, ask the author to select four or defer the comparison; never combine overlapping quartet winners into a ranking.

For a direct comparison, keep the v0.4 candidate set to at most four sketches in one question. Map every stable Choice option ID to its bound image material with `materialOptions`, include a tie or no-preference option, use neutral labels, and inspect the exact request before execution. A four-way question asks which one is best among those four in one response. Pairwise asks six separate two-image questions over the same frozen profile and brief; set `providerSelection.batching` to `singleton` so each question exposes only its own pair. It returns six explicit head-to-head outcomes and can reveal ties or inconsistent relations, at greater call and token use. Preserve those results as a graph; do not infer missing outcomes or force an automatic total ranking. The exploratory six-image spike is not a v0.4 recipe and does not establish universal equivalence between comparison shapes.

Do not compare five or more designs by splitting them across Clef calls, showing a contact sheet, or merging subset winners into a ranking. Ask the user to choose up to four candidates for this study or defer the larger comparison to a later iteration. A local quartet choice answers only which option is preferred within that quartet.

## Script identity and protagonist prominence

When matching a design to a character in a script, state the target character by name if the script contains several and include only the passages needed to judge that character's behavior, dialogue, relationships, role, and tone. Ask about fit to that named characterization, using no more than four bound sketches and authored typed dimensions. Do not substitute the most prominent character for the named target or treat a visual match as a popularity vote.

Example: provide only the script passages that establish Mara as a cautious station engineer and the four selected portraits. Ask separate typed questions about authored cues such as “Does this design fit Mara's cautious approach to risk?” and “Does it fit her role as a station engineer?” Bind each question to the intended portrait or bind all four in a direct Choice that asks which design best fits Mara. Keep option-to-image mappings explicit, include no-fit when appropriate, and do not include unrelated passages about Tomas or Leena merely because they are vivid.

Protagonist prominence is a different construct from visual fit to a character brief. If the question is which design most likely represents the story's lead, identify the relevant narrative evidence, such as scene recurrence, who initiates the central plan, or who resolves the conflict; do not invent an appearance brief. Keep the image set within four, preserve ambiguity, and report the answer as a model judgment over the supplied script evidence.

For example, include the bounded script evidence that Mara appears in every supplied scene, starts the central plan, and resolves the conflict, then ask one four-way Choice: “Which of these four designs is most likely intended to represent the story's protagonist, given only this narrative evidence?” Map each neutral option ID to one bound portrait and include no-fit if none is supported. This asks which supplied character design may represent the narratively prominent role; it does not ask which design matches a heroic or intelligent appearance brief.
