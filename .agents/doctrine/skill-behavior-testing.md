# Skill behavior testing

Sheg skills are behavior-shaping source. Keep scenarios, evaluators, calibration examples, and deliberately retained campaign evidence under the owning skill's `tests/behavior/` tree. The packaged plugin ships guidance but excludes skill tests and campaign artifacts. Shared harness implementation belongs in `scripts/skill-testing/`; deterministic harness tests belong in `test/skill-testing/`.

`npm run verify` runs deterministic repository checks only. It does not dispatch live actors or judges and cannot establish that a skill improves behavior. `test/skill-scenario-harness.test.ts` validates the paired catalog, prompt boundaries, trace schemas, and named historical campaign records. It contains explicit scenario IDs, skill hashes, and historical trial expectations, so a new catalog entry does not automatically gain campaign coverage.

Use `npm run skill:campaign -- prepare --config <file> --output <off-repository-directory>` to freeze scenario request/evidence, evaluator criteria, guidance snapshots/references, execution settings, and (for workflow suites) ordered user turns and private checkpoint expectations. The manifest retains the contents as well as hashes. Comparison requires matching request, evidence, rubric, suite, classification, repetitions, and execution settings. Actor prompts contain only the selected guidance and the current request/evidence. Workflow prompts instruct the actor to use available Sheg MCP tools; future turns and expected tool checkpoints are withheld until their intended role as later user turns or evaluator inputs.

Run or resume with explicit `--backend codex`. The Codex adapter uses bounded concurrency, separate scratch directories, fresh ephemeral focused/discovery sessions, and a persistent per-trial workflow session resumed by its exact session ID. Each Codex process receives a per-attempt `SHEG_DATA_DIR`; after capture, that Sheg run store is copied under the attempt for inspection. This isolates campaign data from the user's regular Sheg store, while tool availability remains ambient. The adapter captures raw event streams, final text, stderr, requested and observed settings, and append-only attempt records. A captured trial is not dispatched again. Runtime errors remain separate from behavior results; a behavior rerun gets a new trial identity. The fake adapter is for deterministic tests only. Live executions are absent from `npm run verify`.

Focused outputs are checked against the actor trace contract and the exported Sheg `runRequestSchema` for executable `run_inspect`/`run_start` proposals. These checks distinguish plausible prose from invalid requests; incomplete design replies are not forced into executable requests. `grade --backend codex` sends retained actor output and the frozen rubric to a separate fresh judge context without an arm label, saves its raw outputs, and validates criterion-level pass/fail/uncertain judgments with evidence. Workflow judgments also receive raw Codex events and the hidden checkpoint expectations. Judge failures stay uncertain and are not converted into behavior failures. `report` emits JSON, Markdown, and escaped static HTML with trial counts, failure categories, missing actor/judge model metadata, raw-output links, and explicit unavailable usage/timing fields.

`compare --baseline <dir> --candidate <dir> --backend codex` first rejects changed comparison inputs, then pairs captured repetitions. A stable hash assigns anonymous A/B labels; two separate judge runs see the same labels in reversed display order. The harness retains both judgments, disagreements, and a separate empty human-adjudication field. It does not provide a command for entering or resolving adjudication, and small-sample outcomes do not imply statistical significance or general reliability.

Calibration fixtures include good, bad, and borderline examples with expected criterion labels and rationale. The current agreement helper reports disputed criteria but does not enforce a minimum score or run a full calibration campaign. Keep articulate invalid requests and unsupported claims among the calibration cases. Judges should cite observed evidence rather than match phrases.

Before changing guidance, select affected capability cases and shared regression safeguards. Compare frozen old and candidate guidance under identical request, evidence, criteria, and execution settings. Use no-guidance only as a separate attribution control. Include relevant discovery near-misses, changed-follow-up workflow cases, and held-out wording where available. Choose repetitions for the risk and record the rationale. Inspect all failures, uncertain judgments, missing metadata, and judge disagreements; never overwrite a failed trial or historical evidence.

Tool-use auditing is an ambient runtime capability, separate from Sheg's harness. Use the installed `/temporary-tool-auditing` procedure when bounded tool-attempt or no-tool evidence is part of a campaign. Verify the positive control, exact subject/session and worktree binding, covered interval, and cleanup. If coverage cannot be verified, label it `not-captured`; do not infer absence from an actor's statement or parent-session coverage of a separate CLI actor. Raw Codex events can show tool activity observed in that CLI stream, but that is not a claim of universal tool isolation. Do not add permanent hooks, telemetry, or tool isolation to Sheg.

Run `npm run verify` before publishing. It is a code-quality and deterministic behavior gate, not a live skill-campaign gate. Keep behavior tests and retained evidence out of customer plugin packages.
