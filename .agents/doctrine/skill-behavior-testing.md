# Skill behavior testing

Sheg skills are behavior-shaping source. Keep each skill's behavior scenarios, evaluators, and retained campaign evidence under that skill's `tests/` directory. The plugin ships the skill guidance; it excludes the skill tests.

Keep deterministic fixture, prompt-boundary, evaluator-pairing, trace-schema, and package-exclusion checks in `npm run verify`. These checks validate the scenario/evaluator catalogs and render prompts; they do not dispatch actors, invoke evaluators, or run a campaign. Use the fixture renderer in `scripts/skill-scenario.ts` so actors receive the current owner skill, only its declared references, and the fixed user request and controlled evidence. Keep evaluator criteria out of actor prompts; run the evaluator separately against the recorded actor trace.

Before changing behavior guidance, run at least five fresh-context trials against the current skill and preserve their outputs. Keep the request, controlled evidence, and evaluator criteria fixed for that baseline. If a guided trial fails or makes an unsupported product claim, run a matched no-guidance control before attributing the result to the skill. After editing, run at least five fresh-context candidate trials with the same request and evidence, then manually inspect every failed, disputed, or flagged judgment. This campaign procedure is not generally enforced by the renderer or CI. The campaign test currently checks five guided baseline and candidate trials, five baseline controls, reused controls, and expected outcomes for the two campaigns it names; adding a scenario to the catalog does not automatically add that campaign coverage. Version the scenario and evaluator together when their tested contract changes; archive superseded evidence instead of rewriting its history.

Actor and control prompts instruct actors to treat fixture results as mock evidence, avoid tools and external services, and propose Sheg actions only. These are prompt instructions, not runtime restrictions: the harness does not prevent or record tool use, paid provider calls, or live study changes. Record `toolUseAudit: "not-captured"`; an actor's claim is not proof that no tools were used. The stored trace schema requires `simulationOnly: true` and `toolUseAudit: "not-captured"`, but does not enforce what those fields mean. `simulationOnly` describes the controlled evidence, not the actor's tool-use state. Campaign conclusions apply only to the tested scenarios and recorded model settings; if the execution route does not expose a setting, record it as unavailable rather than infer it.

Keep evaluators private from actors and judge observable actions and claims against explicit criteria. Retain evidence for both strengths and failures. A canned trace, deterministic test, or one compliant actor does not replace the required fresh-context campaign.
