# Sheg v0.4.0 visual studies roadmap

**Design authority:** [Approved visual-studies specification](../../specs/2026-10-04-v0.4.0-visual-studies.md), approved on 2026-10-12. The specification governs scope and experiment semantics; this roadmap governs dependency order. Read both before writing or executing a child plan.

**Baseline:** Released v0.3.0 and SQLite schema 9. Plans 1-7 are delivered on `develop` through `8ade0ba` (`0.4.0-dev.11`, PR #42). Each ordinary integration PR gets its own unique development identity on the intended v0.4.0 line; planning commits alone do not publish a release.

**Release outcome:** Authors can study article images and placement, supplied rendered A/B treatments, and character brief/script fit using frozen text and images. One durable study can combine capable providers, matched independent branches, compact visual history, and inspectable results. Agents know defaults and override controls rather than routing internals.

## Slice contracts

### Plan 1: durable image preparation

The delivered product can import a verified static PNG/JPEG/WebP, retrieve its exact saved bytes after source removal, scale down the whole image while preserving aspect ratio/orientation, and return a separately inspectable candidate with provenance. The source stays preserved. No provider account or credential is required. Preparation does not imply that a complete inference packet fits. Visual run inputs remain unavailable until Plan 2. Test the processing library inside a copied plugin early; no external ImageMagick, platform image utility, runtime download, or checkout dependency is permitted.

### Plan 2: explicit Clef visual execution

Begin with bounded transient native REST investigation. Probe Choice/Score/Noul, exact question/image binding, text/media/schema pressure, truncation and admission errors. Past small-image success is evidence of transport, not sufficient measurement policy. Define an honest supported envelope before shipping retained hosted execution; unknown fit stays unavailable. Obtain explicit paid-call authority and a finite allowance when this plan is written. If no defensible envelope exists, stop this route and return for a design amendment.

Extend existing material, packet, run and persistence contracts end to end, including transactional run acceptance with all assets. New visual material requires agent/author-supplied alt text. Present current pixels for the authored visual question/group, exclude its descriptor from that pixel prompt by default, then carry descriptor/caption/exact typed response into later history. Explicit pixel reuse and described-evidence questions remain distinguishable. Retain explicit provider selection and old text request semantics in this slice. Secure Cloudflare tokens stay separate from Jev routes and are never persisted or logged. Ship the corresponding operational and agent guidance with the working feature.

### Plan 3: automatic routing with declared constants

Automatic selection evaluates enabled availability, capability, fit, preferences and economy. Freeze catalogue/preferences/constraints at acceptance; select actual units as reached, and persist choices before dispatch. Declared respondent/stimulus comparisons lock provider/model by default, including image/no-image arms, unless the agent explicitly designs a provider comparison. Preserve explicit run-wide and unit/group overrides. Unknown prices are disclosed; no invented cheapest/model-quality claims. Inspection explains unresolved future choices and fingerprints the frozen inputs/policy. Implement singleton versus automatic batching without changing logical independence. No post-dispatch substitution.

### Plan 4: one study, multiple independent histories

Add a domain-neutral matched fork rather than recognizing article prose. Settle the upstream cohort, snapshot reached eligible contexts, and copy each into the declared conditions. Execute the prefix once. Do not merge branch histories, expose sibling treatments/answers, or allocate cohorts implicitly. Branches can continue independently. Combine the selection service, actual ready treatment packets, deterministic topology call bounds and runtime reached admission. Reserve all physical calls against one study allowance. Continue unaffected work, preserve successful counterparts, expose incomplete pairs, and recover only eligible incomplete work with its recorded provider/input. Exercise one-arm timeout, process death, budget exhaustion and restart through real persistence boundaries.

### Plan 5: durable extensions and interpretable matching

Keep existing follow-on modes and source-version checks, with exact branch/evaluation/context handles. Continuing retains text and compact visual history by default; recorded mode retains source delivery; selected pixel reuse is explicit. Allow a retained-material subset including empty, independent of prior-answer inclusion. Preserve descriptions as supplied facts, not model reactions. Visual material links do not inherit text equality rules. Extend deletion and backup to retain every asset required by accepted children and preparation lineage. Reports expose matched/unmatched outcomes, complete-pair denominators, provider evidence and survivor selections without imputation or confidence-scale merging.

### Plan 6: prove and teach the full user-value scope

Exercise both fully exposed hypothetical article placement and reached-only staged reading questions; label their different evidence. Rendered A/B uses supplied captures, records viewport/render/font provenance, and tests whether scaling erases relevant distinctions. Character studies distinguish unprompted traits, prompted brief fit, script-character matching and protagonist prominence. Start at four designs; any additional visual context counts against the same four-image allowance. Compare direct all-four with six independent pairs under the same profile/narrative/provider and appropriate order controls. Report disagreement/ties/cycles and costs; do not invent a tournament winner or automatic numerical equivalence threshold. Bring the findings to the author for the agreed decision: retain dedicated pairwise support only if useful differences justify it. Unsupported required demonstrations require an explicit design/scope amendment, not hidden release omission.

### Plan 7: combined qualification, not deferred ownership

Every previous slice ships its tests, generated assets and usable guidance. This final slice checks the integrated surface, not a backlog of missing implementation. Use a representative released schema-9 store, copied plugin and one article/visual-fork/onward-text study across connections. Verify frozen assets despite import changes/removal, local catalogue changes, failure/recovery without replay, old typed request reads and compatible execution, integrity-checked backup and safe migration failure, and maintenance access for future schemas. Run the repository gate, generate/package explicitly, and prepare reviewable release qualification evidence outside shipped source. Tagging, stable publication and merge require the release workflow and separate authority.

## Handoff notes

Plan 1 isolates the immediate local preparation value and the bundled-codec risk before inference depends on them. Plans 2-5 build shared runtime contracts before testing specialized author recipes. Full release scope remains the approved specification; first-slice convenience does not replace it. Keep planning artifacts on `develop`/feature branches under the release guide's custody policy. Update this roadmap when dependencies, scope or blockers change, rather than appending test receipts or completion narration.

Plan 2 establishes explicit Clef execution only. Plan 3 owns selection policy and locks; it must preserve explicit-provider requests while automatic choice evaluates the frozen enabled catalogue against actual unit inputs and declared equality constraints. Plan 4 owns matched-fork authoring and execution, so Plan 3 defines extensible comparison identities without implementing fork topology.
